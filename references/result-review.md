# 已有成果的角度复核

成果复核是创造性思考的一种使用方式，不是技能唯一入口。选择能够改变当前结果使用方式的视角；只展示与此成果有关的发现。

| 视角 | 看什么 | 避免什么 |
|---|---|---|
| 接收者 | 看完要判断什么，有没有足够依据和明确下一步？ | 未提供证据就断言领导、客户或读者的真实动机 |
| 执行现场 | 第一步谁做，依赖是否具备，失败时怎么办？ | 因为理想方案更完整就超出用户预算与工时 |
| 上下游交接 | 有什么默认大家都懂，却可能影响交付？ | 把所有事项增加审批或会议 |
| 反例 | 什么条件会让结论失效，哪些数据口径不匹配？ | 将想象反例当成事实错误 |
| 使用之后 | 成果发出后下一步由谁继续，怎样知道有用？ | 强制每个成果变成产品、平台或增长项目 |
| 新选择 | 目的、关系、时机或默认动作能否换一种设定？ | 只换词、换标题或加一段普通建议 |

一条有用发现至少连接：成果中的具体内容或缺失 → 可能影响 → 原范围内可改的一步。不要用臆造的因果关系支持它。

缺少资料就说明结论是有条件的。摘要或议程未列细节，不足以证明实际安排缺失；先判断材料本来需要承担什么用途。避免由某条反馈推断所有用户、由已完成推断已验收、由访问或下载推断喜欢。任务约束中的数字不擅自替换。

对已做好且风险可控的结果，不补全所有理论可能。可以保留原稿，只提出一个用户能选择的小变化；没有值得动的变化时明确接受它。

用户希望分享时，可按 assets/discovery-card.md 整理可公开的发现。分享由用户决定，默认不读取额外私有资料、不上传、不添加关注门槛。

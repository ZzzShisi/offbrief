# 工作场景中的创造性判断

从用户给出的真实摩擦入手。下列视角帮助识别关系，不是要求每次都输出六栏表。

| 观察位置 | 有用的追问 | 守住什么 |
|---|---|---|
| 交付与使用 | 做完之后谁在何时使用，使用者的下一步是否清楚？ | 不能未经同意取消原交付 |
| 参与者交接 | 等待、重复确认、返工发生在哪个交接处？ | 不把未提供的人际动机当事实 |
| 决策与证据 | 哪一条新证据会改变当前排序或决定？ | 不制造虚构数字来支持结论 |
| 时机 | 事前准备、执行中辅助、事后反馈能否重新安排？ | 不跳过必要审查 |
| 既有资产 | 哪份已有记录、样例、工具能复用，减少重新制作？ | 查已有上下文，保护私有数据 |
| 资源瓶颈 | 有限时间、人力和预算能先验证哪一步？ | 不提出超出限制的大系统 |

允许提出合理但未确认的诊断；表达为“如果这个摩擦来自……，可以先……验证”。不能把频次最高的反馈直接视为根因，也不能凭一条反馈断言所有人都这样。

如果任务本来就在要方案或分析，把洞察变成该成果的一个选择，不额外制造另一套项目。与用户成果无关的建议丢弃。

# 超纲 OFFBRIEF Skill

[简体中文](README.md) · [English](README.en.md)

**把任务、方案或卡点交给 AI，发现你没想到的另一条路。**

一个让 AI 换个角度思考的创意思考 Agent Skill。

从零开始时，给它一个想法，它帮你找起点；任务卡住时，告诉它做过什么、哪些条件不能改，它帮你探索新办法。要写方案、报告或文案时，有价值的新思路直接融入成果；已有结果时，再让它换个角度检查盲点。

**完成你想到的，发现你没想到的。**

## 一分钟上手

安装并加载后，拿一件正在做的事，直接说：

> 我现在在做____，卡在____。换个方向，帮我想想。

还没想清楚，可以从半个想法开始。已经有结果，可以再补一句：

> 帮我超纲一下，换个角度检查，先别改。

你也可以说“换个方向”“换个角度”“帮我校验思路”。实际是否自动选中技能，由宿主根据描述、上下文与配置判断；需要时可以明确指定「超纲」或 `offbrief`。

## 它解决什么

我们向 AI 提问时，常常已经选好了目标、方法和交付形式。AI 沿着这条路继续写，方案越来越完整，而另一个值得考虑的方向，可能一直没有进入讨论。

工作里容易遇到这样的时刻：

- 方案越补越细，仍然不知道怎样让下一步真正发生。
- 催了很多次，事情依旧卡在同一个等待里。
- 活动办完、报告交完，又开始想：这些成果到底帮谁做出了什么决定？
- 已经有一份不错的结果，想看看自己还有没有漏掉一个有价值的选择。

超纲会把默认前提重新拿出来看：谁一定要先参与，哪一步可以提前，目标是否值得重新考虑，现有成果还能怎样使用。

**让你多看见一个与你的任务有关、值得比较或尝试的选择。**

## 同一个任务，打开新的可能

| 能力 | 你会得到什么 |
|---|---|
| **新做法** | 目标已经明确，换一种参与方式、时序、关系或实现机制。 |
| **新目标** | 再看成果最终要让什么发生，提出值得考虑的目标候选，由你决定是否调整。 |
| **新可能** | 从现有材料、经验、限制或过程产出中，发现可以继续探索的路径。 |

## 设计理念

### 把问题本身也放进思考

理解你要完成什么，也重新看看那些已经习惯的设定：目标为何这样定，谁必须先参与，事情为什么按这个顺序发生。一个默认前提松动，新的做法或目标才有机会进入讨论。

### 让想法走远，再接回现实

允许大胆重构，也珍惜小巧的发现。新想法要说清与任务的联系，再考虑时间、资源、权限与限制；尚未确定的方向，可以先找一个小试法。

### 把创造性融进正在做的事

从半个想法、途中卡点，到方案交付和成果复核，都可以发挥创造性。有用的洞察直接进入成果，让思考帮助工作继续推进。

### 把发现落到一个新的选择

我们关注方法、目标、关系或行为具体会怎样变化。这个选择应当值得比较、尝试或继续探索，让你能说清：“原来这件事还可以这样做。”

### 保留你的判断与决定

把事实、推测和提议分清。是否改变目标、扩大范围或采用新方向，由你决定；已有成果足够好可以保留，精确任务按要求准确完成。

## 工作原理

超纲把一套可复用的思考过程写进 `SKILL.md`，相关方法和边界放在 `references/`，由宿主按需读取。

| 步骤 | 怎样推进 |
|---|---|
| **Brief：读懂任务** | 确认目标、已有事实、做过的尝试和不能改变的限制，找到实际摩擦。 |
| **Branch：探索不同路径** | 重新看默认前提，从参与者、关系、时序、目标等方面寻找有实质差异的选择。 |
| **Bridge：接回现实** | 说明新方向与当前问题的联系，考虑资源、权限与失效条件，必要时给一个小试法。 |
| **Bet：选择值得继续的发现** | 给出最值得关注的方向；需要比较时提供少量不同选项，保留你的决定权。 |

内部可使用前提反转、目标迁移、结构类比、主体交换、时序重排、约束暂时移除和副产品转正等方法，按问题选用。

执行依靠宿主模型。Skill 本身是纯文本指令，没有附带运行脚本；查资料、读文件、生成文件等操作，使用宿主已有且获准的工具。

## 安装

### 让你的 AI 工具帮你安装

在支持 Skills 安装的 AI 工具里说：

```text
帮我安装这个 Skill：https://github.com/ZzzShisi/offbrief
技能名是 offbrief，SKILL.md 位于仓库根目录。
安装后确认加载的是 1.3.0，再让我拿一个正在做的任务试用。
```

安装方法由宿主决定。目录安装时，安装目录名使用 `offbrief`；`SKILL.md`、`references/` 和 `assets/` 要保留相对位置。

### 使用技能 ZIP

下载 [专用技能 ZIP](dist/OFFBRIEF_v1.3.0.zip)，交给支持技能包安装的宿主，按它的导入或安装流程使用。

包内为 `offbrief/SKILL.md`、参考资料、模板与许可证。若宿主要求 `SKILL.md` 在压缩包根目录，按 [安装说明](INSTALL.md#压缩包布局) 调整布局。

Codex 的目录与命令示例、WorkBuddy 的安装问法、更新和最短检查，见 [INSTALL.md](INSTALL.md)。

## 工作场景演示

### 周报一直在等别人，怎样换个方向

以下为 **1.3.0 实际模型测试的模拟工作情境**，尚未在真实部门实施。

**输入：**

> 每周要收六个部门的 Excel，周五上午汇总。表头统一而且不能改，大家经常到周五才发现有一个字段要问别人，催得再勤也晚。不能换系统，也不能给别人新增日报。换个方向，帮我看看能怎么破这个等待。

**实际回答节选：**

> 建议把跨部门字段做成**提前预约的交接**：周五仍交完整 Excel，周中先确认“谁提供、什么时候提供、按什么口径提供”。
>
> 你描述的卡点是：大家填到某一格，才启动向别人求答案。**发现依赖，其实可以早于填写最终数值。** 表头固定，正好能把这部分提前安排。

回答接着建议：先选择一个常卡住的字段，提前确认数据来源、口径和可提供时间，观察周五是否仍需临时找人。也指出，如果数据客观上到周五之后才产生，提前预约无法提前产生数据。

这个新选择改变了交接发生的时机，保留原表头、报送形式和已有系统。是否有用，可以从一组供需双方开始验证。

## 使用方式

| 你现在做到哪一步 | 可以这样说 |
|---|---|
| **刚有想法** | 我想让同事开始用这个工具，还没方案。换个角度，帮我找一个值得试的起点。 |
| **做到一半卡住** | 我已经试了这些办法，这些条件不能改。换个方向，帮我看看还有什么路径。 |
| **需要实际交付** | 直接写一页试点计划，把有价值的新思路融进去，给我一份能用的成果。 |
| **已有结果** | 这份已经做好了。结合原要求帮我超纲一下，换个角度检查，先别改。 |

![刚有想法、做到一半、需要交付和已有结果，随时超纲一下](docs/images/experience.png)

创造性思考可以融入成果，表达也可以很自然。你无需选择内部模式，成果复核是其中一个使用环节。

## 测试与边界

1.3.0 已进行探索、交付、复核、自然发现、精确执行和文件交付的模型测试。测试范围与观察见 [测试记录](docs/TESTING.md)。

使用时保留这些原则：

- 区分事实、推测与新提议，缺少材料时说清条件。
- 给出改变目标或范围的想法，仍由你决定是否采用。
- 尊重已有成果。用户只让检查就不擅自改稿，已有结果足够好也可以结束。
- 只核对数字、翻译、摘录或改指定错字时，按要求准确处理。
- 需要成果就完成成果；有用洞察已经融入时，无需另交一份重复的“创意版”。

输出受宿主模型、上下文与工具能力影响。当前测试验证了这些场景中的行为，没有形成真人偏好或业务改善的统计结论。

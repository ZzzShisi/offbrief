# 1.3.0 测试记录

测试日期：2026-10-13。测试对象：OFFBRIEF 1.3.0。执行环境：本地 Codex，沿用当时配置的 gpt-6.1-sol 与 xhigh；每次使用新的临时会话。

## 测试覆盖

共收集 **27 份实际模型回答**：

| 类型 | 数量与说明 |
|---|---|
| 新版文本请求 | 15 个请求，涵盖开始探索、推进破局、完整交付、成果复核、逻辑校验、精确计算与翻译等。 |
| 编码补测 | F14 再运行 1 次，确认以 UTF-8 完整读取后仍只返回译文。 |
| 同题对照 | 前四个工作场景分别与普通请求和 1.2.0 对照，共 8 份回答。 |
| 自然发现 | 2 次，任务提示中不写技能名或技能路径。 |
| 实际文件交付 | 1 次，读取模拟 CSV 并创建 Markdown 文件，原 CSV 哈希不变。 |

27 是模型回答数量。当前记录没有真人盲评、显著性分析或采用人数统计。

## 观察到的行为

- 未成稿时直接探索；用户要成果时完成交付。
- 已有成果按材料复核，区分摘要未提供的信息与已证实的缺陷。
- 逻辑校验不把他人的动机或推测写成事实。
- 只核对数字、只翻译、锁定修改范围时遵守精确要求。
- 成果已经足够时接受不增加建议。
- 目标改变作为提议保留用户选择权。
- 两次自然发现均观察到正文读取，属于该环境下的两次结果。
- 文件交付测试实际创建了文件，证明可与宿主工具配合。

公开的 [模拟题输入](evidence/cases.json)、[阶段示例](EXAMPLES.md) 与六份未改写的完整模型回答，可用于核对这些观察。完整开发记录仍在本地保留；本仓库不附带运行会话与机器路径日志。

## 结论能说明什么

这些运行支持“全过程可用、按需发挥创造性、尊重精确要求与用户边界”的设计。普通请求与旧版在部分题目中也给出了相近的方向，现有对照没有证明新版创造力全面超过普通 AI。

实际输出仍需接回任务条件。F03 的“预算为零”应按输入修正为“不新增预算”；模型自拟的时间、数量和 20% 门槛是建议，不能作为已实现结果。提前交接也可能增加协调负担，要通过真实使用继续判断。

## 平台范围

自然发现与文件交付观察来自本地 Codex，不代表所有宿主必然以相同方式调用技能。

已收到的 WorkBuddy 1.2.0 安装与试用报告属于旧版反馈；没有将其改写为 1.3.0 的 WorkBuddy 环境结论。新版在实际宿主中的安装与调用，按 [安装后检查](../INSTALL.md#安装后最短检查) 验证。

欢迎在 Issues 分享真实任务中的选择、采用情况和无用工作。每条新反馈都应标明环境与条件，再决定是否调整技能。
